# 第 06 章 讯息涟漪的错峰出现

手机里的三个气泡共用一段动画，开始时间分别错开。旁边的信号圈也在循环，手机本身缓慢浮动。这个例子不需要 JS 计时器，适合从 CSS 时间安排入门。

打开 [TelegramSignal.tsx](../../src/animations/TelegramSignal.tsx) 和 [TelegramSignal.css](../../src/animations/TelegramSignal.css)。组件只负责 DOM，动作全部在 CSS 中。

## 手机与消息分别定位

手机宽 65px、高 112px，绝对定位在舞台中心。顶部缺口和三个消息都以手机为参照。消息分别位于距顶部 28px、51px、74px 的位置，左右各留 8px。

手机浮动时，里面的消息会随父元素一起移动。气泡自己的动画只需要处理水平偏移与透明度，无需重复计算手机的纵向位置。

这种父子分工很常用。先让整组元素一起动，再给组内成员增加小变化，结构比给每个元素重复完整坐标更容易维护。

## 把 3.5 秒换成可以理解的时刻

`telegram-message-in` 的周期为 3.5s。

| 关键帧位置 | 对应周期时刻     | 目标状态                      |
| ---------- | ---------------- | ----------------------------- |
| 0% 和 20%  | 0s 和 0.7s       | opacity 为 0.35，向右偏移 4px |
| 45% 和 75% | 1.575s 和 2.625s | opacity 为 1，回到原位        |
| 100%       | 3.5s             | 回到半透明和 4px 偏移         |

20% 至 45% 之间逐渐出现，75% 至 100% 之间退回起点。其他关键帧之间按指定的缓动插值。它们并没有完全消失，最低透明度仍为 0.35。

三个气泡的延迟分别为 0、0.8、1.6 秒。这会把同一段循环错开，形成先后感。延迟不是每轮末尾额外增加的停顿，动画开始后按各自的周期继续运行。

## 正延迟的第一轮要单独观察

当前气泡没有设置 `animation-fill-mode: backwards`。第二、第三个气泡在首次正延迟期间，仍可能使用普通样式的默认透明度和位置，随后才进入关键帧。

如果你希望它们从页面第一帧起就呈现等待状态，可以为消息动画设置 `backwards`，或者给基础样式写出同样的初态。这个练习能帮助你区分“循环已经运行后的顺序”与“页面刚出现时的顺序”。

负延迟则从周期内部开始，适合让循环从一开始就呈现错相状态。两者用法见 [MDN animation-delay](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/animation-delay)。

## 信号圈也没有一直向外扩散

两个圆圈分别为 35px 和 54px。它们使用 3.2s 周期，在 0.85 与 1.18 倍大小之间往返，同时改变透明度。第二个圆圈延迟 1.2s。

因此，当前效果是呼吸式放大再缩回。想做雷达波那种不断向外扩散、消失后重新出现的效果，需要让关键帧走向更大的终点，并在末尾把透明度降到零。提示词应写清这两种行为中的哪一种。

手机的周期为 4s，角度从 -7 度摆到 -2 度，再回去。它与消息、信号圈的周期不同，整体画面不会每一秒都一起起落。

## 练习修好首次延迟

给消息补上等待初态，再刷新页面观察前两秒。第二、第三条应先保持半透明，随后依次出现。运行十几秒，确认之后的循环节奏没有被改坏。

```text
请阅读 src/animations/TelegramSignal.tsx 和 TelegramSignal.css。
修正第二、第三个气泡在首次正延迟期间可能先完整显示的问题。
保留 3.5s 周期以及 0、0.8s、1.6s 延迟，让等待期间呈现关键帧起点的 0.35 透明度和 4px 右移。
只改消息气泡的必要 CSS，手机和信号圈保持原样。
验证首次加载前两秒、后续循环及减少动态效果，运行 npm run build。
说明采用 fill-mode 或基础初态的原因。
```
