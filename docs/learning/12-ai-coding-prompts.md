# 第 12 章 用完整提示词从零生成动画

把一份完整规格交给没有见过这个项目的 AI，它就能知道要画哪些图形、怎样运动，以及该用什么技术实现。第 01 至 09 份提示词对应九张已有动画，第 10 至 13 份帮助 AI 为新产品构思并实现动画。每份都可单独复制使用。

## 给新商品或新产品元素设计动画

如果还没有目标效果，先选[产品创意生成器](../prompts/10-product-idea-generator.md)。替换其中的产品名称、想强调的特点和希望的感受，AI 会提出三种动作构思，选择一个后完成实现。默认值已经填好，直接复制也能得到榨汁杯演示。

另外三份分别处理[实体商品的结构与材质](../prompts/11-physical-product.md)、[数字产品的信息变化](../prompts/12-digital-product.md)和[产品元素的状态反馈](../prompts/13-product-element.md)。它们要求动画表达具体用途，例如耳机开盒、记录归组或上传完成，漂浮和发光只作辅助。

这些提示词把预备动作、主要变化、结果反馈和复位写进要求。新动画需要说明用户怎样触发、重复触发时怎么处理，以及静态模式下怎样保留功能。

## 复制时带上整个文本块

每份提示词已经包含独立任务所需的信息。

- 技术与交付写明 React、TypeScript、Vite，以及独立组件、CSS、运行命令和构建要求。
- 画面规格给出部件尺寸、相对位置和配色，并安排文字与阴影。
- 动作部分定义关键帧、周期、延迟或计算公式，说明实际要出现的效果。
- 播放要求包括手动暂停、重播、离屏、后台和系统减少动态效果。
- 验收项列出输入状态与可见结果，供生成后逐项检查。

文本块内没有“先读某个现有组件”这样的前置任务。前九份的目标规格已完整填写；后四份提供可替换的产品输入和完整默认值。组件名称是在要求 AI 新建文件时使用的名称，不代表你必须提供同名源码。

## 素材与生成方式

多数图形直接由 CSS 或内联 SVG 构成。Claude 提示词已经带上标志 SVG，可以直接创建本地文件。Duo 的表情和肢体动作保存在 Lottie JSON 中，因此提示词提供可独立下载的 JSON 与海报地址，并要求运行时改用本地资源。

要保持 Duo 的原始动作，需要取得这两份素材。下载不可用时，应当明确报告缺失，不能把整张海报的简单浮动称为相同的角色动画。

## 修改提示词时，保留完成条件

想让终端更安静，可以把最大位移从 ±8px 改为 ±4px；想让星轨更慢，可以把 18s 改为 24s。先改一个数值，保留其他运动与验收条件，生成结果才便于比较。

如果要换技术栈，应当同时说明替代框架、状态管理和资源加载方式。只改开头的框架名称，后面仍要求 React Hook，会让规格互相矛盾。

其他动画章节末尾保留了基于本项目源码的小练习。从空目录生成时，使用本章链接的完整提示词；阅读和修改现有代码时，再用相应章节的练习。
