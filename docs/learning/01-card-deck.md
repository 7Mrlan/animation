# 第 01 章 层叠之间的四张卡片

把指针移进第一张动画，四张卡片会展开。移开后，它们重新叠起，前面的卡片沿左侧抽出，向下移，再回到最后。读完这一章，你应该能指出每一段动作发生的时间，并知道该改哪个数值。

准备好 [CardDeck.tsx](../../src/animations/CardDeck.tsx)、[CardDeck.css](../../src/animations/CardDeck.css) 和 [subscription-motion.ts](../../src/lib/subscription-motion.ts)。组件负责驱动，CSS 画卡片，最后一个文件计算姿态。

## 从四个初始姿态看起

`poses` 中每一项依次表示水平位移、垂直位移和旋转角度。单位是 px、px 和 deg。

| 叠放位置 | x   | y   | 角度 |
| -------- | --- | --- | ---- |
| 最前     | -13 | 17  | -7   |
| 第二层   | 0   | 5   | 0    |
| 第三层   | 12  | -5  | 7    |
| 最后     | 24  | -15 | 14   |

卡片先用 `left`、`top` 和 `translate(-50%, -50%)` 定位到中心附近，再加上这些偏移。每张卡高 110px，常规宽度为 174px。高度还写进了旋转包围盒的计算，所以改卡片尺寸时，要同时检查 CSS 和数学函数。

`index` 表示本轮哪张卡片在最前面。`slot = (i - index + 4) % 4` 把固定的卡片编号转换成当前叠放位置。DOM 顺序保持稳定，姿态和层级随轮次变化。

## 把一轮动作摊开

`DECK_CYCLE_MS` 为 5770。下面的区间来自 `deckTimeline`，左端包含，右端不包含。

| 逻辑时间 ms  | 阶段    | 画面任务                     |
| ------------ | ------- | ---------------------------- |
| 0 至 3000    | hold    | 保持叠放，留出观看时间       |
| 3000 至 3180 | prepare | 保持起始姿态，进入准备阶段   |
| 3180 至 4080 | extract | 最前一张向左抽出             |
| 4080 至 4575 | lower   | 抽出的卡片下移，其余卡片补位 |
| 4575 至 5430 | return  | 抽出的卡片回到队尾           |
| 5430 至 5590 | settle  | 保持终点姿态                 |
| 5590 至 5770 | hide    | 保持终点，等待下一轮编号切换 |

移动部分共 2250ms。函数先算出它的进度，再按 0.4 和 0.62 分段。

```ts
const progress = (elapsed - 3180) / 2250
```

`prepare` 和 `hide` 是阶段名，当前实现没有让它们各自触发一段额外的位移动画。观察源码时，要继续跟踪这些名称被谁读取，不能只凭名称猜效果。

5770ms 是逻辑循环长度。组件在挂载、恢复等情况下还有 600ms 的姿态收束窗口，单帧时间差也限制到最多 64ms，因此不要把它当成任何运行条件下都精确一致的秒表周期。

## 先绕开，再换层级

旧卡直接穿过卡堆，会显得像纸片互相穿透。`deckFrame` 先估算旋转后的半宽，再求出所有卡片最左侧的位置，让旧卡从更左边退出，并留出 18px 间隔。

抽出阶段，旧卡仍在最上层。进度到 0.4 后，它被放到最底层，其余卡片可以补上来。回程开始时，新前卡的文字可见标记随之切换。

这里要把两个现象分开观察。`visible` 布尔值控制哪张卡片应该显示文字，CSS 的 opacity 和 blur 仍有过渡。测试能验证目标标记的数量，实际淡入淡出的像素表现还要到浏览器里看。

## 插值让动作接得上

`mixPose` 做逐项线性插值。若起点是 0，终点是 20，进度为 0.25，结果就是 5。传入数组以后，同一条公式可以处理 x、y 和角度。

```ts
a.map((value, i) => value + (b[i] - value) * t)
```

时间轴在插值前使用 `6t⁵ - 15t⁴ + 10t³` 平滑进度，让每段起步和结束更缓。展开或收回时，组件又用 `1 - Math.exp(-delta / 80)` 逐步靠近目标姿态，减少交互打断时的突变。一个负责阶段路径，一个负责当前姿态向新目标过渡。

循环边缘还有 180ms 的交接处理。它不额外冻结逻辑时钟，下一轮仍继续推进。

## 展开时为什么能放进窄卡片

`fanFrame` 将四张卡排成两行两列，每张倾斜 4 度。它先计算旋转后占用的宽高，再分别根据舞台宽度、高度求可用缩放值，最后取较小值，且不超过 0.7。

这段实现明确针对四张卡片。`poses`、取模运算和两行两列布局都写着四张的条件。想改成六张，需要一起改数据、循环和展开布局，仅追加两行 JSX 会让姿态计算失去对应关系。

## 做一个能验收的练习

先把停留从 3000ms 延长到 4200ms，其他动作持续时间保持不变。后续分界点都要顺延 1200ms，总周期应变成 6970ms。只修改总周期会把多出来的时间留在最后一个阶段，得不到预期的开头停留。

运行 `npm test`。现有测试以 10ms 间隔采样检查文字标记与层级，还检查循环首尾位置和几种宽度的展开几何。它们没有覆盖所有浏览器渲染与输入行为。再用鼠标、键盘和触摸分别展开一次，确认交互仍能收回。

```text
请阅读 src/animations/CardDeck.tsx、CardDeck.css 和 src/lib/subscription-motion.ts。
把叠放后的 hold 时长改为 4200ms，prepare、extract、lower、return、settle、hide 的持续时间保持现值。
把相关时间分界放在同一处计算，避免只改总周期造成多余尾部停顿。
保持四张卡片的路径、层级交接、文字标记和展开布局。
更新对应时间轴测试，验证循环衔接，运行 npm run check。
说明新的阶段时间表，并分别报告自动测试与浏览器检查结果。
```
