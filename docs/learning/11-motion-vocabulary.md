# 第 11 章 把动画感觉写成可执行的术语

“更轻一点”可以是速度慢一些，也可以是位移小一些、阴影淡一些。与 AI 合作时，先指出对象，再选一个可测的参数，通常比不断追加形容词更容易得到想要的效果。

下面的词表按本项目出现的问题分组。右栏可以直接作为提示词中的一句要求，数值是示例，使用前按目标卡片调整。

## 时间和节奏

| 中文与英文             | 在代码里表示什么             | 可以怎样说                                    |
| ---------------------- | ---------------------------- | --------------------------------------------- |
| 周期 duration          | 一轮动画的时长               | 把信封周期从 5s 改为 7s，路径不变             |
| 幅度 amplitude         | 一次往返的最大位移或角度变化 | 主体最多上移 4px，旋转变化不超过 3deg         |
| 正延迟 delay           | 动画首次开始前等待多久       | 三个消息分别延迟 0、0.8、1.6 秒               |
| 负延迟 negative delay  | 从周期中途开始               | 第二个星点从 4s 周期的中点开始                |
| 交错 stagger           | 同类元素错开时间             | 每个节点比前一个晚 200ms 开始                 |
| 缓动 easing            | 时间进度如何映射到变化进度   | 上下浮动使用 ease-in-out，匀速旋转使用 linear |
| 停留 hold              | 一段时间保持某个姿态         | 前卡停留 4200ms 后再开始抽出                  |
| 阶段 phase             | 时间轴中有名称的区间         | 到 return 阶段再切换前卡文字标记              |
| 往返 alternate         | 相邻轮次改变播放方向         | 让位移在两端之间往返，不重置到起点            |
| 无缝循环 seamless loop | 首尾能连续衔接               | 验证循环最后一帧与下一轮首帧的几何关系        |
| 离散变化 steps         | 数值分段跳变                 | 文字光标用 steps 闪烁，不做渐隐渐现           |

不要把 `reverse` 和 `alternate` 当作同一个设置。前者按反方向播放既定序列，后者让相邻轮次交替方向。若关键帧本身已经对称往返，单独加 reverse 可能看不出明显变化。

## 位置和空间

| 中文与英文                  | 在代码里表示什么           | 可以怎样说                                 |
| --------------------------- | -------------------------- | ------------------------------------------ |
| 位移 translation            | 元素向某个方向移动         | 抬升 3px，保留原来的居中位移               |
| 旋转 rotation               | 绕变换原点转动             | 角度在 -4deg 与 0deg 之间循环              |
| 缩放 scale                  | 改变显示尺寸               | 最大缩放 1.04，不改变布局宽高              |
| 变换原点 transform origin   | 旋转与缩放围绕的位置       | 让纸片绕左下角轻摆                         |
| 参考框 reference box        | 百分比变换据以计算的框     | 说明 -54% 相对于哪个元素的高度             |
| 视差 parallax               | 多层元素使用不同位移幅度   | 光圈完整跟随，终端最大只移动 8px           |
| 归一化 normalization        | 把原始范围转换成统一范围   | 将指针坐标转成 0 至 100 的百分比           |
| 夹取 clamp                  | 把数值限制到上下限内       | 将输入坐标限制在 0 至 100                  |
| 回中 recenter               | 离开后恢复初始位置         | pointerleave 后把两个坐标恢复为 50%        |
| 线性插值 lerp               | 按进度混合起点与终点       | 使用当前姿态作为起点，平滑靠近展开目标     |
| 堆叠上下文 stacking context | 一组元素内部比较层级的范围 | 检查 isolation 和 transform 对层级的影响   |
| 包围盒 bounding box         | 图形旋转后占用的矩形范围   | 用旋转后的宽高计算展开缩放，避免越界       |
| 裁切 clipping               | 隐藏超出容器的内容         | 保留 overflow hidden，核对最大位移时的边缘 |

本项目没有真正的三维卡片翻转。若请求 `rotateY`、透视或背面隐藏，属于增加新效果，需要交代三维空间、遮挡和文字可读性，不能把现有二维旋转直接叫作 3D 翻牌。

## 形状和质感

| 术语                     | 对应的实现               | 更明确的要求                            |
| ------------------------ | ------------------------ | --------------------------------------- |
| 伪元素 pseudo-element    | `::before`、`::after`    | 用两个旋转方块画信封折角，保持 DOM 简单 |
| 遮罩 mask                | 用图形轮廓限制可见区域   | 保留本地 SVG mask，只调整填色           |
| 径向渐变 radial gradient | 从某个中心向外变化的颜色 | 光圈中心跟随指针，外缘渐变到透明        |
| 边缘高光 inset highlight | 浅色内阴影或细边框       | 在舞台上沿保留一条低透明度高光          |
| 分层阴影 layered shadow  | 多层不同半径与偏移的阴影 | 近处阴影窄一些，远处阴影更淡            |
| 呼吸 pulse               | 大小或透明度缓慢往返     | 光圈在 0.8 至 1.1 倍之间呼吸，周期 5s   |
| 拖尾 lag                 | 视觉位置晚于输入目标到达 | 给准星 100ms 坐标过渡，终端幅度不变     |
| 静态姿态 resting pose    | 没有动画时的完整外观     | 移除动画后保持主体居中且可见            |

“弹簧 spring”通常涉及刚度、阻尼等参数，或者明确的弹簧计算。当前 CardDeck 使用平滑插值，并没有物理弹簧模型。要保留现有实现，就描述“逐步靠近目标且不超出终点”；要增加回弹，则另外说清幅度与停止条件。

## 更新和生命周期

| 术语                        | 本项目中的意义                      | 请求时要说明的条件                         |
| --------------------------- | ----------------------------------- | ------------------------------------------ |
| RAF 合帧                    | 下一帧只处理最近一次输入            | 保留最新坐标，避免每个事件各排一个回调     |
| ref                         | 保存 DOM 或可变值，不主动触发重渲染 | 把高频坐标放进 ref，保留业务状态在 state   |
| state                       | 变化后让 React 更新组件             | 展开、筛选、是否暂停等交互状态继续用 state |
| 卸载清理 cleanup            | 取消请求、回调或监听器              | 多次筛选重挂载后，不留下旧播放器实例       |
| 回退 fallback               | 主要内容失败时仍能展示的内容        | JSON 加载失败后显示对应海报                |
| 减少动态效果 reduced motion | 遵循用户的系统动态偏好              | 停止循环，保留完整静态画面和必要操作       |
| 暂停 pause                  | 保留当前进度并停止推进              | 暂停主要循环，说明是否还允许过渡走完       |
| 重播 replay                 | 从初始状态重新开始                  | 明确采用重挂载还是播放器定位接口           |
| 重绘 paint                  | 浏览器重新绘制内容                  | 性能优化前记录绘制开销，避免只猜瓶颈       |
| 合成 compositing            | 把已绘制的层组合显示                | 不把 transform 或 will-change 当成性能保证 |

## 将一句感觉改成一条需求

| 起初的表达   | 可以继续明确为                                                           |
| ------------ | ------------------------------------------------------------------------ |
| 做得高级一点 | 只改外卡片，保留内部动画；使用浅色细边框与低透明度阴影，悬停抬升最多 3px |
| 动画太晃     | 将终端指针幅度从 ±8px 降到 ±4px，自动浮动周期保持 5.6s                   |
| 跟手一点     | 只减少装饰光标的坐标过渡时间，保留 RAF 合帧和坐标夹取                    |
| 不要卡       | 在目标设备复现卡顿，记录性能轨迹，按证据修改最耗时的一处                 |
| 改成通用组件 | 列出要公开的参数和默认值，明确哪些尺寸或卡片数量仍是固定约束             |

每一条明确需求都应该能回答两个问题。代码里哪一部分会变，修改后看什么才能判断完成。接下来可以用[提示词模板](12-ai-coding-prompts.md)把它整理成完整任务。
