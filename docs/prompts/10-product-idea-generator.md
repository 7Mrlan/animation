# 10 从产品特点构思新动画

这是一份从产品特点产生新创意的完整提示词。可以替换块内的产品输入；不替换也能按默认案例直接生成。

```text
请从空目录创建一个可以运行的单卡片动画演示。你只需要这份规格，不需要原项目、截图或之前的对话。直接完成实现。

技术与交付
使用 React、TypeScript 和 Vite，Node.js 24，普通 CSS，系统字体。选择互相兼容的依赖版本，开启 TypeScript strict。除本提示词明确列出的素材或播放器外，不增加 UI 库、动画库或远程资源。
创建 package.json、HTML 入口、React 入口、演示页面、独立动画组件与对应 CSS。提供 npm run dev、npm run build、npm run preview 和简短 README。使用清楚的组件及类名前缀，允许同一页面放多个实例。
有文件和终端工具时实际创建文件、安装依赖并验证构建；只有文本输出能力时，按文件给出完整代码和运行命令，并说明哪些检查没有执行。

产品输入
产品名称默认“便携榨汁杯”。
想让人记住的特点默认“把水果块变成均匀果汁，杯体方便携带”。
受众默认“浏览产品卡片的普通用户”。
希望的感受默认“清爽、轻快、有一点惊喜”。
用户可替换以上四项。没有替换时直接按默认值完成，不需要其他资料。只表达提供的特点，不能自行补充真实产品的功率、续航、健康效果或销量。

先从产品里找动作
识别一个主物件、一种与它有关的材料或信息，以及一个能被看见的变化。动作要能让人理解这个产品做什么。
用不超过三行的表格提出三种不同构思，每种写清触发、主要动作、结束反馈和所用技术。三种构思应有不同的动作关系，不能只换颜色或循环速度。
从中选一个最能表达产品特点且能在小卡片里读清的方案，说明选择理由，然后直接实现完整代码。不要停在等待确认，也不要只输出创意清单。

创意约束
主动作从产品本身产生。例如物体打开后露出内部、零件有顺序地组装、材料被混合、信息重新排列，或一个物件把内容交给另一个物件。
漂浮、发光、旋转可以作为辅助，但不能承担全部创意。去掉产品名称后，观众仍应能通过图形和动作猜出大致用途。
一次只突出一个主要变化。安排短暂的预备动作anticipation，再出现主要动作，最后给出结果反馈和自然复位。避免所有元素同时抢着运动。
选择一个有意义的交互，让指针、点击或键盘触发结果。交互不是单纯把整张卡放大。
使用一种基础材质和一个强调色。阴影应帮助区分物件前后，装饰粒子最多18个，不加无关彩纸或全屏烟花。

默认产品的视觉与动作起点
默认榨汁杯可以画成透明杯体，内部有几块几何水果，液面有一条细波纹。通过SVG clipPath把水果与液体限制在杯体内，盖子和杯体分别成层。
一次主动作可安排为0至250ms杯盖轻微压下，250至1300ms果块沿杯内路径转动并逐渐变小，1300至1800ms液面变得均匀，1800至2300ms回到安静的展示姿态。保持少量残余纹理，避免把杯内变成空白。
每次触发只执行一轮，完成后等待下一次输入。待机只保留低幅度液面变化。水果归位的复位过程要平滑，不能在清晰可见的中央突然闪回。
如果采用另外一种更好的构思，请给出同样具体的时间分段、位移范围和复位方法，再实现它。产品输入被替换时，要重新选择符合新产品的物件和变化。

卡片与实现范围
只做一张最大宽400px的产品动画卡，舞台高280px、圆角18px，下方放产品名和一句简短说明。页面背景#f7f6f3，外卡片白色、圆角24px、内边距10px，边框#ece8e1，投影低透明度。默认舞台采用#fff2dc和#f0f7e6，强调色#ef8d4a；换产品时允许重新选择合适的低饱和配色。
优先使用SVG、DOM和CSS。用clipPath或mask表达容器，用stroke-dashoffset表达线条被画出，用父子transform拆开定位与动作。只有确实需要连续路径计算时才使用RAF，不能为简单循环堆计时器。
每个SVG实例的渐变、遮罩和裁切ID必须唯一。所有图形自行绘制，不获取未提供的商标或产品照片。给出产品数据与动画组件分开的结构，方便以后更换产品文案。

本任务的验收重点
能用一句话说清“用户做了什么，产品里的什么发生了变化，最后得到什么反馈”。检查动作是否与输入特点一致、关键内容是否可读，以及连续快速触发会不会叠加多个时间轴。若视觉比喻只在说明里成立而画面读不出来，简化结构后再交付。

播放与可访问性
在舞台左下角放两个独立按钮，分别控制暂停或继续、从头重播。按钮尺寸至少 32px，有中文 aria-label 和清晰的键盘焦点，按钮自身不要跟随内部图形运动。
初始进入页面即可看到完整构图。使用 IntersectionObserver 观察舞台，露出比例达到 0.08 时才允许自动播放，并结合 document.hidden 和手动暂停状态共同控制。切到后台或离屏后停止主要循环，回来时只在手动暂停未开启的情况下恢复。
CSS 动画通过 animation-play-state 暂停，覆盖普通元素和伪元素；JS 时间轴取消 RAF；播放器使用自身暂停接口。恢复时重置上一帧时间戳，避免把后台停留时间算进动画。
监听 prefers-reduced-motion。开启时停止装饰性循环与跟随位移，展示清楚的静态构图；必要的展开或切换可以立即完成。任何 Effect 都要清理监听器、观察器和待执行的回调，确保 React StrictMode 的重复创建与清理安全。

完成后的验收
检查 320px、768px、1440px 宽度，页面没有横向滚动，标题和按钮不被动画遮住。分别检查首次加载、动作复位、暂停继续、重播、离屏返回和静态模式；存在循环时再检查首尾接缝。
验证同页两个实例互不影响，卸载后没有继续运行的时间轴或播放器。运行 npm run build，报告执行结果；无法运行的检查写明未执行。最后用短说明解释关键帧、坐标与交互之间的关系。
```
