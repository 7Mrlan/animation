# 13 新产品元素的状态反馈动画

这是一份从产品特点产生新创意的完整提示词。可以替换块内的产品输入；不替换也能按默认案例直接生成。

```text
请从空目录创建一个可以运行的单卡片动画演示。你只需要这份规格，不需要原项目、截图或之前的对话。直接完成实现。

技术与交付
使用 React、TypeScript 和 Vite，Node.js 24，普通 CSS，系统字体。选择互相兼容的依赖版本，开启 TypeScript strict。除本提示词明确列出的素材或播放器外，不增加 UI 库、动画库或远程资源。
创建 package.json、HTML 入口、React 入口、演示页面、独立动画组件与对应 CSS。提供 npm run dev、npm run build、npm run preview 和简短 README。使用清楚的组件及类名前缀，允许同一页面放多个实例。
有文件和终端工具时实际创建文件、安装依赖并验证构建；只有文本输出能力时，按文件给出完整代码和运行命令，并说明哪些检查没有执行。

元素输入
元素默认“文件上传状态卡”。
它的用户任务默认“选择一份文件，观察上传进度，知道成功或失败”。
需要的状态默认idle、uploading、success、error。
可替换成收藏按钮、优惠券、会员卡、通知徽章或其他产品元素。替换后先重新定义用户动作和状态，不要把上传剧情强加给其他元素。

从状态变化寻找创意
先提出两个具体的动效方向，分别写清用户动作、视觉变化和完成信号。选择信息最清楚且有一点意外的方向，直接完成可运行组件。
让动效解释状态。进行中要能看出进展，成功要有一次短促确认，失败要提供可理解的停顿或回退。避免用不断旋转的装饰替代全部状态。
给每个状态定义稳定的静态画面，确保暂停、弱设备或减少动态效果时依然能操作。互动元素使用真实button与可见焦点，动画装饰不抢点击。

默认上传卡的完整方向
卡片中间是一张带折角的文件图形，旁边有文件名“设计稿.pdf”和进度轨道。初始文件图形完整，轨道为空。
用户点击“模拟上传”后，文件底部的一小片几何纸带伸向进度轨道，暗示内容正在被传送。纸带只在uploading状态运动，不能挡住文件名或进度文字。
组件接收status和progress参数，progress范围0至1。轨道长度严格映射真实传入的progress，用clip-path或scaleX表现，不用独立计时器伪造组件进度。
在独立演示页里可以用明确标为“模拟”的控制器推进progress，并提供“成功”“失败”“重置”按钮。组件本身只根据传入数据表现状态，不能声称真的上传了文件。
到success时，用300ms让纸带收回，文件折角复位，再用400ms描出勾号。完成后保持成功姿态，不继续发射粒子。
到error时，停止纸带，用120ms、3px以内的单次横向回退表达中断，保留当前进度与文件名，显示“重试”动作。不要让整张卡剧烈抖动或反复闪红。
重试从明确的初始状态开始，清理上一轮动画；如果业务选择从已有进度继续，应当通过参数显式表达。

技术与术语
使用React、TypeScript、普通CSS和内联SVG。组件接口清楚列出status、progress和onRetry。用状态机决定哪些元素可见，用progress-driven animation让视觉进度与数据一致。
文件折角可以用伪元素或SVG路径，勾号使用pathLength=1配合stroke-dasharray与stroke-dashoffset描线。将progress放进CSS变量或内联样式，事件驱动更新，不为静态状态保留RAF循环。
暂停只影响纸带和确认动作等装饰动画，进度数值、轨道长度与状态文字仍及时反映最新props；不可用旧画面误导用户。
把反馈持续时间分别写明，避免一个通用transition all影响全部属性。不同状态切换中断时取消旧动画，最后画面应对应最新props。

视觉方向
页面背景#f6f7f9，卡片最大宽400px、24px圆角、白底、12px内边距，舞台高260px、背景#eef3f9。主色#5b78a1，文字#35455b，成功色#5f9476，错误色#b56c66，颜色不要承担唯一状态信息。
文件图形约92×118px，浅白纸面、细边和柔和投影，折角18px。进度轨道高5px，末端圆角。留出独立文字区域说明状态，图形不能把百分比或操作按钮压住。
如果元素输入被替换，仍然交付可复用接口、稳定状态与明确反馈，并为新元素重新设计几何、颜色和时间参数。

本任务的验收重点
依次输入0、0.25、0.5、1，轨道的视觉进度对应这些值。中途切到error或重置不会继续播放成功动画。快速更新props只显示最后状态。动画停用时，按钮、文件信息和成功失败含义仍然清楚。

播放与可访问性
在舞台左下角放两个独立按钮，分别控制暂停或继续、从头重播。按钮尺寸至少 32px，有中文 aria-label 和清晰的键盘焦点，按钮自身不要跟随内部图形运动。
初始进入页面即可看到完整构图。使用 IntersectionObserver 观察舞台，露出比例达到 0.08 时才允许自动播放，并结合 document.hidden 和手动暂停状态共同控制。切到后台或离屏后停止主要循环，回来时只在手动暂停未开启的情况下恢复。
CSS 动画通过 animation-play-state 暂停，覆盖普通元素和伪元素；JS 时间轴取消 RAF；播放器使用自身暂停接口。恢复时重置上一帧时间戳，避免把后台停留时间算进动画。
监听 prefers-reduced-motion。开启时停止装饰性循环与跟随位移，展示清楚的静态构图；必要的展开或切换可以立即完成。任何 Effect 都要清理监听器、观察器和待执行的回调，确保 React StrictMode 的重复创建与清理安全。

完成后的验收
检查 320px、768px、1440px 宽度，页面没有横向滚动，标题和按钮不被动画遮住。分别检查首次加载、动作复位、暂停继续、重播、离屏返回和静态模式；存在循环时再检查首尾接缝。
验证同页两个实例互不影响，卸载后没有继续运行的时间轴或播放器。运行 npm run build，报告执行结果；无法运行的检查写明未执行。最后用短说明解释关键帧、坐标与交互之间的关系。
```
